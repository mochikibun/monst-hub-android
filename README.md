# MONST HUB v0.3.1 — 全機能版
Android 8.0以上。Android Studio不要、GitHub ActionsでAPKを生成できます。



## v0.3.1の使い勝手の変更
- **新規インストール時のアカウントは0件**です。ホームの「最初のアカウントを追加」からメイン・サブなどを登録してください。旧版で登録済みのアカウントは勝手に削除しません。
- ホームの「所持キャラ・図鑑」を押すと、まずアカウント選択画面が開きます。編集対象の垢を選んでから図鑑を開きます。
- 選択した垢の一覧では、各キャラの **−／＋** でその場で所持数を1体ずつ増減。入力欄への数字入力は不要です。
- 詳細画面の体数編集も−／＋です。0体で保存すると、その所持記録を削除します。
- キャラは **スマホで横3列** のコンパクトなカード表示。大きい画面では4〜5列になります。アイコン・名前・属性・形態・所持数を表示します。
- **通常一覧・検索結果・全垢横断検索のすべてでアイコンを表示**します。画像を取得できない場合も、名前や所持数は表示され、編集できます。
- 画像はGameWith図鑑の公開画像URLから必要な分だけ読み込みます。キャラ画像をAPKやZIPに同梱しません。取得済みの画像は端末キャッシュから表示します。
- アカウント選択画面の「全垢をまとめて横断検索」、または図鑑内の「全垢で横断検索」で、従来の横断検索を利用できます。
- 全垢表示では合計所持数を表示。キャラをタップすると垢別の内訳を確認できます。編集時には対象の垢を選びます。
- 実・ラック・育成メモが異なる記録は別のまま保持します。＋は空の育成記録へ追加、−は空の記録を優先して減らします。育成済み等の記録が複数ある場合は、詳細から減らす記録を選んでください。
- 更新・個別追加・厳選リストは「更新・個別追加・育成メモ」を開くと表示されます。図鑑の自動更新は引き続き有効です。
- 旧版の図鑑キャッシュに画像識別子がなくても、名前や所持記録を残して移行します。新形態の画像が出ない場合は一度図鑑を手動更新してください。

## v0.3から継続する機能
### 黒×白のホーム
日課／絆／所持キャラ・図鑑／キャンペーン／4垢チーム／オーブ管理を上部に配置。
「計画・攻略ノート」「アカウント・設定」はタップで開閉します。アカウント編集・URL・バックアップは後者にあります。
配置案の画像は `docs/home-monochrome.png`（実機スクリーンショットではありません）。

### 所持キャラ・図鑑の検索
1. ホーム →「所持キャラ・図鑑」→「図鑑を取得／更新」を押します。
2. 初回はインターネット接続が必要です。現在の取得サイズは約17MB。処理中は完了まで待ってください。
3. 先に対象の垢、または全垢横断を選びます。名前・読み・図鑑番号と属性・所持のみで検索し、48件ずつ表示します。
4. 一覧の−／＋で所持数を変更。実や育成メモを記録する場合はキャラをタップし、詳細から編集します。
5. キャラ詳細に、どの垢に何体いるか表示されます。「厳選・育成中」から未完了の育成だけ確認できます。
6. 複数体で実や育成状態が異なる場合は、別の所持記録として追加してください。同じ状態の複数体をまとめることもできます。

取得元はGameWithの公開「モンスター評価図鑑」が利用するデータです。2026-10-18の確認では**9,282件（形態別）**。
アプリには生の図鑑データやキャラ画像・評価文を同梱せず、端末で取得し、番号・名前・略称・属性・形態・アイコン識別子など検索に使う項目をSQLiteに保存します。アイコンは表示する分だけ取得し、端末にキャッシュします。
ゲーム公式APIではありません。図鑑番号の分からないレコードは番号を空欄にします。GameWithの内部IDをゲーム内の図鑑番号として表示しません。
収録件数は実際に保存した件数、日時は取得日時（JST）です。ゲーム内全件との一致は保証しません。
自動更新は約24時間ごととアプリを開いたときの確認に対応します。初期設定はON・従量課金でない通信のみ（Wi-Fiなど）。設定からOFFや通信条件を変更できます。初回・手動で直ちに試すときは更新ボタンも利用できます。省電力や通信制限で自動更新は遅れることがあります。アプリを強制停止した場合は再び開く必要があります。
更新失敗・重複ID・不正な内容の場合は全体を取り消して前回の図鑑を残します。
図鑑更新で自分の所持数は書き換えません。掲載されなくなった所持キャラは保存した名前等から引き続き検索できます。
- 取得元ページ：https://xn--eckwa2aa3a9c8j8bve9d.gamewith.jp/article/show/423909
- 公開データ：https://firebasestorage.googleapis.com/v0/b/walkthrough-tool.appspot.com/o/monst%2Fmaster%2Fcharacters.json?alt=media

### 自分で追加する新キャラ・新形態
「＋ 新キャラ・新しい進化形態を個別追加」で名前・属性・形態・任意の番号を登録します。
図鑑のキャラと同じ検索画面に表示されます。「個別追加」の表示で区別します。
別のIDで保存するため、同名でも勝手に統合しません。図鑑更新でも消えません。
個別追加したキャラは詳細画面から編集できます。新形態を別に管理したい場合は編集ではなく追加してください。
後から図鑑に同じキャラが掲載されても、自動統合・所持数の移動はしません。

### 4垢チームと一括チェック
1〜4垢を選んでチームを作成。「まとめて完了／未完了にする」で絆または日課を選択します。
そのチームの垢だけが更新されます。メンバー以外の記録は変わりません。

### 月間・期間限定ミッション
名前、管理月、任意の期限・メモを登録。垢ごとに「未着手／途中／クリア済／報酬受取済」を管理します。
未受取のみの表示と期限順の並びを用意。次月用に複製すると管理月と期限が1か月進み、進捗は初期化されます。
イベントを自動収集する機能ではありません。複製後の正しい開催日時は自分で確認・編集してください。

### 運極・周回目標
垢、キャラ・クエスト名、現在値、目標値、使用チーム・周回メモ、任意の期限を保存します。
現在値が目標以上なら達成扱いとなり、その目標の期限通知は止まります。

### 攻略編成ノート
クエスト名、最大4枠の担当垢・キャラ名、実・紋章・立ち回りなどのメモを保存。
スクショを1枚添付できます。長辺が約1280px以下になるよう縮小しJPEGにして端末内へ保存します。
スクショもJSONバックアップに含まれます。キャラ画像の切り抜き・画像認識による所持数自動入力は今回未実装です。

### オーブ目標と獲得予定
垢ごとに目標残高を設定。予定の内容・個数・期限を登録すると、現在の残高と未回収予定を分けて表示します。
「回収して残高へ加算」は履歴に記録し、同じ予定を再加算できないようにします。
既に残高へ手入力で反映した場合は「残高を変えず回収済み」を選んでください。

### 期限通知
設定で通知を許可し、ミッション・周回目標・オーブ予定の各記録で通知をONにします。
期限の0〜168時間前を指定可能。報酬受取済・達成済・回収済の記録は通知しません。
再起動後に再設定します。通知は端末の省電力などで遅れる場合があり、正確な時刻を保証するアラームではありません。
強制停止されたアプリは再び開くまで通知できない場合があります。

### 日課と絆の切替を別々に設定
既存の先輩向け設定（4時）を維持し、「アカウント・設定 → 設定・バックアップ」で別々の時刻を選べます。
日課4時／絆0時などの組み合わせにも対応します。手動リセットは引き続き絆の当日分のみです。

### データの引き継ぎ
管理データの保存形式をschema_version=2へ更新しました。v0.2のschema_version=1のバックアップも読み込めます。
同じ署名で上書き更新した場合は保存済みデータをそのまま利用できます。
ただしdebug署名が違ってアンインストールが必要な場合は、**削除前に旧版でバックアップを保存**してください。
バックアップ対象には図鑑自動更新の設定、個別追加キャラ、所持・育成記録、全ての新しい管理機能と編成スクショを含みます。
GameWith図鑑のキャッシュ本体は再取得します。復元直後でも保存済みの個別キャラと所持記録は検索できます。
上限は20MB（画像も含む）。元データは壊れたバックアップや保存失敗で上書きしません。

## 基本機能（v0.2から継続）
- 黒×白のホーム：登録数、日課完了垢数、合計オーブ。
- サブ垢管理：新規利用時は0垢。メイン・サブなど必要な垢を自分で追加します。名前・メモ編集、追加・削除（最大100垢）。
- 日課：全垢共通の項目を自由に追加・削除。初期はログイン／日課／書庫／神殿。垢ごとに手動チェック。
- 絆：アカウントごとの当日完了チェック。毎朝4時（日本時間）に新しい日付の未完了へ切替。当日分を全垢まとめて戻す手動リセットも用意。
- オーブ：垢ごとの残高入力、増減の記録、メモ。合計残高と最近の履歴（最大50件表示、保存は最大10,000件）。
- マルチURL：各垢に自分用URLを1つ保存・コピー・外部アプリで開く。http/httpsのURLに対応。URLの自動発行や他人への共有機能はありません。
- キャンペーン：従来のカレンダー、月移動、日付タップ、カテゴリフィルタ、日別属性、更新日時、通信失敗・degraded表示を維持。
- 設定：日課と絆それぞれの切替時刻変更、JSONバックアップ保存・復元。
- データは端末内に保存。名前・日課・オーブ等は手動入力で、ゲームとの自動連携はありません。友達の端末とは別々に保存されます。

## すでにGitHub Desktopを使っている方向け：入れ替え手順
1. `MONST-HUB-v0.3.1-project.zip`を右クリック →「すべて展開」。
2. GitHub Desktopで `monst-hub-android` を選び、必要なら「Fetch origin」→「Pull origin」で最新状態にします。
3. 「Repository → Show in Explorer」で同期フォルダーを開きます。
4. 展開した中の `.github`、`app`、`docs`、`gradle` と、それ以外のファイルすべてをコピーし、同期フォルダーに貼り付けます。同名ファイルは置き換えます。
5. **同期フォルダーや `.git` フォルダーは削除しません。** 今回は先に既存ファイルを消す必要もありません。
6. GitHub Desktopで変更を確認し、Summaryに `v0.3.1 図鑑の使い勝手を改善` と入力 →「Commit to main」→「Push origin」。
7. リポジトリの「Actions → Build Android APK」を開いて最新の実行がSuccessになるまで待ちます。
8. 実行画面の「Artifacts」（上部の件数リンクからも移動できます）→ **MONST-HUB-debug-apk** をダウンロードしZIPを展開。中の `app-debug.apk` がアプリ本体です。

ZIPはAndroidプロジェクトが直下にある構造です。ZIP自体や外側のフォルダーをGitHubに入れず、展開した中身を入れてください。
既存Discord BOTとmonst-hub-feedのフォルダーでは作業しません。

## インストール・更新
- APKをAndroidへ転送して開きます。必要な場合、そのファイルを開くアプリの「この提供元のアプリを許可」を有効にします。
- v0.3.1はversionCode=4。同じ署名なら既存版へ上書きできます。
- **この作業環境で作ったAPKとGitHubで作ったAPK、または別のActions実行のAPKではdebug署名が異なる場合があります。**
- 上書きに失敗した場合は、旧MONST HUBの「設定・バックアップ」から先にバックアップを保存してからアンインストールし、新版で復元してください。旧v0.1はカレンダーのみで、管理データはまだありません。
- 今後、管理データを入力した後はアンインストール前に必ずバックアップしてください。バックアップには端末の外で選んだ保存先を使えます。
- APKは個人・友人向けdebug版です。Playストア向け公開署名は今回の対象外です。

## 絆と日課の切替
初期設定は毎朝4時・日本時間です。例：10/19の03:59までは10/18分、04:00から10/19分を表示します。
アプリを閉じていても次に開いたときに当日分を表示します。開いたままなら約15秒以内、チェック操作時にも日付を再確認して切り替えます。バックグラウンド常駐や通知権限は不要です。
前日の記録を消す方式ではなく、日付ごとに別の記録を持ちます。過去の日課・絆はバックアップにも含まれます（過去分の閲覧画面は未実装）。
絆画面の手動リセットは**当日の全垢の絆のみ**。日課、オーブ、昨日以前の記録は残ります。リセット前には確認が表示されます。

## バックアップ
ホーム →「アカウント・設定」→「設定・バックアップ」→「バックアップを保存（JSON）」で保存先を選びます。
復元は「バックアップから復元」でJSONを選び、内容が正常な場合のみ確認後に全管理データを置き換えます。キャンセル・形式違い・壊れたJSONなら現在のデータは変更しません。
対象：アカウント名・メモ・URL、日課項目・日付別チェック、絆、オーブ残高・履歴、切替時刻。
キャンペーンの取得済みキャッシュは対象外です。オンライン時に取り直します。
バックアップは20MB以内。端末内データが読めない場合は自動で初期化せず、復元を案内します。

## 通信と保存
管理機能はオフラインで使えます。キャンペーンを開いたときに以下の2つをGETします。図鑑更新時は上記のGameWith公開データへGETします。
- https://raw.githubusercontent.com/mochikibun/monst-hub-feed/main/public/campaigns.json
- https://raw.githubusercontent.com/mochikibun/monst-hub-feed/main/public/status.json

サーバーへの管理データ送信はありません。マルチURLや掲載元を開いた場合は、外部アプリ・ブラウザーがそのURLを処理します。
degradedの注意表示は変更していません。

## 開発・検証
JDK 17 / Gradle 8.11.1 / AGP 8.9.2 / compileSdk・targetSdk 35 / minSdk 26。
Wrapper一式、テスト、Actions設定を同梱。Windowsは `gradlew.bat testDebugUnitTest lintDebug assembleDebug`、Actionsは `bash ./gradlew --no-daemon testDebugUnitTest lintDebug assembleDebug`。
Android環境準備には `packages: platform-tools` を明示し、配布終了した旧toolsを要求しません。
自動テストはRobolectricを含みます。実図鑑データのローカル検証用テストはMONST_CATALOG_FIXTURE環境変数を渡した場合にのみ実行します。通常のActionsではこの1件だけスキップし、合成データで取り込み・検索・復旧を検証します。
追加機能の構造は `docs/ARCHITECTURE.md`、検証の範囲は `docs/VALIDATION.md` を参照。
